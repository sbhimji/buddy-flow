# Mini-spec 3.2 — Breadth [F17, F18]

Status: **open** (written 2026-08-16, Sunday evening — pulled forward at the
owner's request to ride the trader view Monday). Story: DEV-PLAN Phase 3 →
3.2 ("the easy momentum win").

## What

Per basket: how many members are persistently outperforming SPY since the
open. Three-state per member (outperform / in-line / underperform) with a
dead-band and a persistence filter; rendered as the raw fraction so
small-basket evidence is visibly weaker (a 2/3 is not an 8/9).

    ret(sym, m)   = LastTradePrice(sym, [open, end of minute m)) / anchor(sym) − 1
    diff(sym, m)  = ret(sym, m) − ret(SPY, m)
    state(sym, m) = ↑ if diff > +band; ↓ if diff < −band; · otherwise
    member counts ↑ (or ↓) iff state is ↑ (or ↓) for the last P completed minutes

Rendered: `breadth` = `up/N` over full membership (trader + dev);
`breadth_detail` = `u↑ i· d↓` (dev view only — the dev plan's
"hover/detail" surface, terminal edition).

## Decisions

- **B1 — Consumed defaults, flagged not asked.** Dead-band ±10 bps (D7
  default), reference point since-open (D8 — must match 3.6 RelPerf when it
  lands), persistence P = 3 consecutive completed minutes (dev-plan
  default). All tunable at the nightly ledger review like every default.
- **B2 — Prices are the raw tape's last print** (`bucket.LastPrice`,
  unfiltered by class), at 1-second resolution. Honesty note: a late
  NON_PRICE_FORMING print can briefly misprice a member; the dead-band and
  fraction-over-members damp it to at most one count. A price-forming
  "last" is 3.3's concern; revisit then. New read-only store methods
  `FirstTradePrice` / `LastTradePrice` (ascending/descending scan, early
  exit) — no storage change, 1-second-store invariant untouched.
- **B3 — Anchor = the earliest traded second in [open, now)**, its last
  price. When the capture spans the open this is the opening-auction
  second for liquid names (the official-open admin print duplicates the
  cross price ~1ms later, same second). On a mid-day capture (08-14
  rehearsal starts 11:51) the anchor is the first captured price — the
  code is correct, the data partial, same caveat as cum_share there.
- **B4 — Gaps, never fake counts.** Before P completed session minutes:
  gap (first breadth at 09:33 — the z columns gap through the same open
  minutes). SPY unmeasurable in any needed window: gap. A member without
  an anchor or a price in every needed window is *unmeasured* — it folds
  into the in-line middle (denominator stays full membership); a basket
  with ZERO measured members gaps ("0/9" would be a fake statement).
  Ties/edges: state boundaries are strict inequalities beyond the band.
- **B5 — Correlation-blind, stated (F18).** ETF arbitrage moves members
  mechanically; breadth cannot tell a crowd from an index print. Noted in
  the package doc and this spec; per the dev plan it is one Glow input,
  never standalone — its v0 trader-view seat is observational, and the
  footer defines it as a measurement only.
- **B6 — Homes.** `internal/breadth` (calc + the two columns, per-render
  price memoization on the single render goroutine, same posture as
  flowshare's winSnap). Wiring: devview registry only — trader set gains
  `breadth` (passed into `flowshare.TraderColumns` as a composed column),
  dev view registers both columns. No renderer changes beyond the
  existing seams. SPY resolved from the symbol table at construction;
  missing SPY errors loudly.
