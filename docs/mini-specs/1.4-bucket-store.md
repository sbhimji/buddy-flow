# Mini-spec 1.4 — Bucket store [F7]

Status: **resolved 2026-08-14** (criteria 1–3 on the replayed 2026-08-13
capture; criterion 4's first live close-write is Monday 2026-08-17 — see the
DEV-PLAN 1.4 status for results). Story: DEV-PLAN Phase 1 → 1.4.
Decisions taken in discussion 2026-08-13/14 (D1–D6 below).

## What

Per-ticker, per-1-second aggregation of every processed print and quote,
held in RAM for the whole session and persisted per session. This is the
first durable *processed* data in the system: the future-ML dataset, the
replay scrubber's source, and the substrate every Phase 3 metric reads.
One resolution — 1 second, all session; coarser views are derived, never
stored (CLAUDE.md invariant; no 10:00 seam).

Wires `internal/classify` into the pipeline for the first time: every trade
is classified (0.3 policy) and its bucket carries per-class splits, so each
metric can select its counting slice (CONTINUOUS for flow; +BLOCK,
+NON_PRICE_FORMING for $vol; DUPLICATE/NON_FLOW stored never counted;
UNKNOWN quarantined+tripwired) without re-deriving policy.

## Decisions (settled 2026-08-13/14)

- **D1 — Buckets key on SIP timestamp** (event time), never receive/process
  time. Invariant-grade: identical buckets from live, instant replay, and
  paced replay is what makes replay acceptance meaningful. Implementation
  keys buckets by absolute epoch-second (`sip_ns / 1e9`) — no session-bounds
  config, no date assumptions in the hot path.
- **D2 — RAM-resident, mutable until write-out.** The bucket store is
  *derived* data; the capture is the durable record, so crash recovery is
  replay-and-regenerate, not file recovery. Late prints (TRF stragglers)
  amend their true bucket in RAM — no close watermark, no seam. Live
  persistence: final write at close (atomic tmp+rename). *(Amended
  2026-08-14: the periodic mid-session snapshot was implemented, then removed
  to keep the review surface small — recovery is replay-and-regenerate
  anyway, so the snapshot was observability, not durability. Revisit
  alongside 3.0, which owns live visibility.)*
- **D3 — Record fields:** trade count / share volume / dollar volume /
  last price / last SIP ts; per-class (count, shares, dollars) for all nine
  0.3 classes; quote count. Signed volume (3.3) is *not* pre-reserved as
  columns — the CSV is self-describing (header), so 3.3 adds columns without
  breaking old files.
- **D4 — Format:** CSV with header, one file per session
  (`data/buckets/<date>.csv`), rows sorted (second, symbol) — second-major.
  Gzip after session close alongside capture compression.
- **D5 — Sparse:** rows exist only for (ticker, second) with activity.
  Zero-materialization (F13: 0/positive = 0; whole-universe-silent =
  carry-forward-blank) is the *reader's* job, not storage's.
- **D6 — Quotes: count only** (activity/data-quality signal). No NBBO
  snapshot per bucket — book state is reconstructable from capture; 3.3
  writes classification results, not book state.
