Status: **resolved 2026-08-24** — 26 zips (07-20..08-24) downloaded and converted, 0 decode errors, one zip re-converted byte-identical; unit suite green; parity day recorded below
(written 2026-08-24). Story: DEV-PLAN Phase 7 → 7.5. Gated by 7.4 (resolved).

**Parity finding (F3, 08-20, live capture vs full-tape buckets):** outside
the 09:30 minute the two are essentially identical — 780,736 of 780,894
(sec,symbol) rows byte-identical, gross premium within 0.04%, and the only
rows where live exceeds tape are the 5 prints the tape later scrubbed as
canceled (the wire delivers them; F1 confirmed). **All 10,379 missing prints
(0.18% of the day) sit in the 09:30 minute** — the pre-open read-deadline
cycling put a reconnect (and 189 re-joins) in flight as the opening burst
hit. Systematic, not a one-off: opening-minute prints live vs tape were
51,016 vs 62,571 on 08-21 and 53,515 vs 69,606 on 08-24 (18–23% of the
open lost daily). Fixed in `uwfeed.readDeadline` (pre-open deadline lands
at 09:30:30, never earlier; 30s in-session; 15 min otherwise) and
`bin/live-options` rebuilt 2026-08-24 evening; 08-25's opening minute is
the verification. **F2 amended:** until a live day matches its tape at the
open, the full tape is the bucket/baseline source for every day it exists;
live capture serves the real-time path and same-day replay.

## What

The 20-day baseline corpus from the vendor's daily full-tape zips
(`/api/option-trades/full-tape/{date}`, published same evening — 7.0):

- Download: `data/full-tape/<date>.zip`, `.part`+rename, existing complete
  zips skipped (resumable). One CSV per zip, whole market (~1.5 GB zipped,
  ~4 GB raw, 10–11M rows). Done tonight with a shell loop following the
  endpoint's 302; a Go downloader is not worth its own code yet.
- Convert: `uwfeed.StreamFullTape(zip, universe, pipeline)` streams the
  CSV, filters to the 189-symbol universe locally, maps REST column names
  to the wire decoder's (`option_chain_id`→option_symbol,
  `upstream_condition_detail`→trade_code, Postgres timestamp → epoch ms,
  Postgres array literal → JSON tags) and runs each row through the SAME
  `normalizePrint` → pipeline → classifier → `optbucket.Store` as live.
  `cmd/uw-backfill` drives it over a date list, writing
  `data/buckets-options/<date>.csv` (7.4 naming rule), skipping dates that
  already have a bucket file (resumable).

## Decisions

- **F1 — Canceled rows are skipped** (`canceled='t'`): a canceled print
  is not a print. Counted; the parity day says whether the live wire ever
  delivers them.
- **F2 — Live capture wins where both exist.** For a date with a
  production capture, the bucket file comes from replaying the capture,
  never from the zip; the zip is the parity referee, not the source.
- **F3 — Parity is measured, not assumed.** On an overlapping day
  (08-20), compare live-capture buckets vs full-tape buckets per
  underlying: prints, contracts, gross premium, net conviction. The
  discrepancy rate is recorded in data.md; anything beyond dedupe/late-
  print noise is investigated before profiles are built on the mix.
- **F4 — No synthetic frames.** The zip is not rewritten as a fake
  capture; provenance stays honest (the bucket header could carry a
  source tag in a future column).

## Done when (on recorded data)

1. Unit: a synthetic 3-row zip (one non-universe row, one canceled row,
   one good row with a Postgres timestamp and array-literal tags) converts
   to exactly one bucket with hand-checked fields; timestamp/array parsers
   table-tested.
2. One zip converts deterministically (twice → byte-identical CSV).
3. Parity day (F3) documented.
4. ≥20 lookback bucket CSVs on disk, weights-stamped, plus the 3 live
   days.
