## What

`internal/conviction` — the read-time z layer for the two signed basket
series, and the columns that render them in `cmd/replay-options -view-at`:

    conv_z = zguard.Z(minute Σ net_conviction, MedianNetConv, SigmaNetConv, floor_basket_netconv)
    net_z  = zguard.Z(minute Σ net_notional,   MedianNetNotional, SigmaNetNotional, floor_basket_netnotional)

for the last completed minute against the basket's day-level profile at
the matched minute-of-day. The existing snapshot columns (cum sums, sweep
share, last-minute sums) stay; two z columns join them.

## Decisions

- **V1 — Nulls render "·"** (zguard's defined null: σ_used 0, non-finite
  input, or the basket profile below `MinProfiledDays`) — never a fake 0.
- **V2 — Basket profiles, not member sums of ticker profiles** (7.6 P-rules,
  3.1 D2): the z compares the basket's summed minute against the basket's
  own day-level baseline. Per-ticker profiles exist for future per-member
  columns; unused here.
- **V3 — Stamps enforced at load**: the view loads profiles with the
  current weights stamp and current basket membership; a stale artifact
  refuses the whole view rather than rendering a blended number.
- **V4 — Footer is a statement of measurement** and passes the no-buy/sell
  substring scanner (mirrored from flowshare's test): "ask-side minus
  bid-side", "calls positive puts negative", "vs 20d matched-minute
  median/MAD".
- **V5 — Profiles optional at the command line**: without `-profiles` the
  snapshot renders sums only, as today; with it, the z columns appear.

## Done when (on replayed recorded data)

1. Unit: hand-built profile + floors → known z; null paths (few days,
   σ=0 with floor 0, missing profile); footer scanner passes.
2. Replay of a production session with real profiles renders z columns;
   two renders byte-identical.
3. One basket-minute z recomputed independently in Python from the
   bucket CSV + basket profile + floors matches the rendered digit.

## Decisions consumed

## Runbook — first live use (2026-08-25)

The capture starts itself at 08:20 CT (launchd, `bin/live-options`, deadline
fix in). **The trader's screen:** `http://<studio>:8788` — the twin of the
equity view on :8787. Two LaunchAgents (installed 2026-08-24):
`com.buddyflow.followoptions` runs `tools/follow-options.sh` at 08:25 CT
weekdays (follows today's capture, writes frames to `data/live-options.log`,
waits for the file if it starts first, exits when the session manifest
lands); `com.buddyflow.liveviewoptions` serves that log on :8788, always on.
Both are read-only followers — killing or restarting them never touches the
capture. Manual equivalent, in tmux any time after the open:

    go run ./cmd/replay-options -follow \
        -capture data/capture-options/2026-08-25/stream.jsonl \
        -profiles data/profiles-options

Re-renders every 5s of event time; exits when the session's manifest lands.

Paced replay — watch a recorded day unfold exactly as the trader would
have seen it (the `cmd/replay -view -speed` equivalent):

    go run ./cmd/replay-options -capture data/capture-options/2026-08-24/stream.jsonl \
        -view -speed 60 -pace-from 09:30:00 -profiles data/profiles-options

Post-hoc snapshots (any time, on the finished or still-growing file):

    go run ./cmd/replay-options -capture data/capture-options/2026-08-25/stream.jsonl \
        -view-at 10:30:00 -profiles data/profiles-options

Reading the table: `cum_net_$` is where premium went (ask-side minus
bid-side, calls positive puts negative); `cum_conv_$` is the same premium
conviction-weighted (the taxonomy — a sign flip vs cum_net means the raw
flow was low-conviction plumbing); `conv_z`/`net_z` compare the last
completed minute to that minute-of-day's 20-day median/MAD. Day-one
baselines: computed correctly (independently verified), not yet watched.

Evening: verify the opening-minute fix — the 09:30 minute of the live
capture should match that evening's full tape (7.5 parity script). The
baseline roll (zip download, `uw-backfill`, `profiles-options`) is done by
`bin/nightly` (`com.buddyflow.nightly`, 22:00 CT — mini-spec 8.1); to re-run
a night: `bin/nightly -date <date>`.
