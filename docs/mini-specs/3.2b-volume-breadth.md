# Mini-spec 3.2b — Volume breadth [F17, F18]

Status: **open** (written 2026-08-17). Story: 3.2 extension per the backlog
entry "Volume breadth — how many members are up ON volume" (owner request
2026-08-16). Amended same day at owner request: `up_on_vol` takes a trader
view seat immediately (overriding the backlog's earn-the-seat default);
`vol_detail` stays dev-only. The seat remains observational — the nightly
ledger still grades whether it stays.

## What

3.2 counts members up on *price*; §2.5's rationale — "one stock up is news;
nine up on volume is money" — wants the conjunction. Two member-level counts
per basket, computed at read time from existing per-ticker profiles and the
1-second bucket store (no new storage, no baseline rebuild):

    rvol(sym, m)  = counted $vol(sym, minute m) / MedianDollars(sym, matched minute m)
    vol(sym)      = $ (unusual) iff rvol > k for EACH of the last P completed minutes
                    · (unmeasured) iff any needed MedianDollars = 0 or no profile
                    (normal otherwise)
    up_on_vol     = members that are BOTH persistent-↑ per 3.2 AND $ per above

Rendered (dev view): `up_on_vol` = `x/y` — of the y members 3.2 counts
persistently ↑, x are also running unusual volume (`7/9` is money, `1/9` is
drift); `vol_detail` = `u$ m·` — members on unusual volume / unmeasured,
direction-blind (high `$` with mixed price breadth reads two-sided fight).

## Decisions

- **VB1 — Defaults, flagged not asked (ledger-tunable like every other):**
  k = 1.5 (lenient end of the backlog's 1.5–2.0 because persistence already
  applies); persistence P = 3 completed minutes, deliberately the SAME
  windows as 3.2's price persistence so both gates describe the same span.
  Per-minute rvol against the matched-minute median, NOT a trailing-sum
  ratio — summing per-minute medians into a window baseline is the
  medians-don't-commute sin D7 exists to avoid; per-minute persistence
  damps single-minute lumps without it.
- **VB2 — Both sides of every rvol use `profile.Counted`** (no auctions) —
  the same policy source the 2.1 profile builder used to store
  `MedianDollars`, so live and baseline count the same prints.
- **VB3 — Thin names (2.1 posture):** matched-minute median 0 → no basis →
  member unmeasured (`·`), folds to the middle; never a fake "unusual". A
  member with no profile is likewise unmeasured (devview.New guarantees
  profiles for all members in the wired path; the rule still holds).
- **VB4 — Gaps, never fake counts.** Before P completed session minutes:
  both columns gap. `up_on_vol` additionally gaps whenever 3.2 breadth gaps
  (SPY unmeasurable, zero price-measured members) — its denominator IS the
  3.2 up count and the two cells must reconcile on screen. `vol_detail`
  needs no SPY and renders on price-gapped rows. Zero volume-measured
  members → BOTH columns gap: an `x/y` or `0$` over wholly unmeasurable
  volume would present "cannot measure" as "measured zero". A price-↑
  member that is volume-unmeasured counts in y, never in x. Threshold is a
  strict inequality (rvol exactly k → normal).
- **VB5 — Correlation-blind, stated (F18), and worse here:** ETF arbitrage
  prints real volume in every member mechanically, so on macro days the
  counts saturate universe-wide and read as broad accumulation. Read
  relative to what every basket shows, not in isolation; noted in the
  package doc. Observational, one future Glow input, never standalone.
- **VB6 — Homes.** `internal/breadth/volume.go` (`VolCalc`: wraps the 3.2
  `Calc` for price sides — 3.2's per-member tally is extracted, not
  duplicated — plus the store and per-ticker profiles; per-render
  memoization on the single render goroutine, same posture as the price
  memos). Wiring: `devview` exposes its already-loaded per-ticker profiles
  read-only; `cmd/replay` dev mode registers both columns; the trader set
  (both commands) gains `up_on_vol` composed into
  `flowshare.TraderColumns` next to breadth, defined in the footer,
  unstyled (no highlight until ledger evidence says which threshold
  deserves one).
