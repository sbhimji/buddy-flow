# Mini-spec 2.2 — σ guard [F13]

Status: **open** (written 2026-08-15). Story: DEV-PLAN Phase 2 → 2.2.
Written for implementation by a fresh session — context pointers included.

## What

The single gate every z-score in the system passes through:
`σ_used = max(σ_measured, floor)`, floor recomputed at every profile build,
and a literal σ=0 yielding a **defined null** — never an exception, never
±Inf. Applies to every current and future z (FlowShareZ first; bond
velocity z and DeltaRatio z when they exist). Enforcement is architectural,
not disciplinary: the only exported z function **takes the floor as a
required argument**, so "forgot the guard" is not an expressible program.

Why it exists: 2.1 profiles use median/MAD (`internal/profile`, `robust()`).
A thin ticker printing identical volume in a minute bucket on 11+ of 20 days
has MAD = 0 — stored honestly as `sigma_* = 0` (never invented away) — and
any unguarded z would divide by zero exactly where the tape is thinnest.

## Decisions (settled in discussion 2026-08-15)

- **D1 — Homes.** `internal/profile` grows the floor computation (floors are
  derived from profiles, so they belong with the builder). A new, tiny,
  dependency-free `internal/zguard` owns the z function — future metrics
  (bond velocity z) have no profile and must not drag one in:
  `zguard.Z(value, center, sigma, floor float64) (z float64, ok bool)`.
- **D2 — Floor definition (per accepted D5, Appendix B).** Per series
  family, per ET minute-of-day bucket:
  `floor(minute, family) = frac × median across the universe's tickers of
  sigma_family(ticker, minute)`, default `frac = 0.25`. Families in v1 are
  exactly the two profiled stats: counted shares and counted dollars.
  Recomputed in the same run as every profile build ("nightly").
- **D3 — Persistence.** Floors written by the profile build into the profile
  dir as `_floors.csv`: header comment line recording the fraction and
  build inputs, then `minute_of_day,sigma_floor_shares,sigma_floor_dollars`,
  390 contiguous rows (09:30=570 .. 15:59=959). Same conventions as every
  other file: self-describing header, atomic tmp+rename, shortest-round-trip
  float formatting, byte-deterministic. Reader validates contiguity like
  `profile.Read` does. The leading underscore keeps it out of any per-ticker
  namespace; consumers read floor *values*, never the fraction.
- **D4 — "Config, not code" (D5's letter), POC-sized.** The fraction is a
  `cmd/profiles` flag `-sigma-floor-frac` (default 0.25) — changeable
  without recompiling, recorded in `_floors.csv`'s header. It graduates to
  real engine config when the nightly-ledger tuning loop (6.5) exists.
- **D5 — Null semantics.** `ok=false` iff `max(sigma, floor)` is 0, or any
  input is NaN/±Inf. The caller renders a gap (F13's defined null). σ=0
  with floor>0 is NOT null — producing a finite z there is the guard's
  entire purpose. No panics anywhere on any input.

## Done when (all on replayed recorded data)

1. Synthetic near-zero-σ series produces bounded z: unit test with the F13
   construction — constant-volume ticker (MAD=0) against a floor computed
   from a small synthetic universe.
2. Degenerate-input table test: σ=0 with floor=0 → `ok=false`; NaN/Inf
   inputs → `ok=false`; no panic, no Inf escapes.
3. Floors build from the real 20-day profiles (the existing
   `data/profiles/`, built `-through 2026-08-13`) for the full universe in
   the same `cmd/profiles` run; two builds byte-identical.
4. Spot sanity on real data, printed by the build: floor at 09:35 vs 13:00
   for both families — open-minute floors should be visibly larger (volume
   σ scales with volume). Reported, not gated.

## Context pointers for a fresh session

- Read `CLAUDE.md` first; invariant: "σ guard before every z" — this story
  IS that invariant. Conventions live in `internal/profile/profile.go`
  (median/MAD, `fnum`, atomic write, contiguity-validating reader) and
  `internal/bucket` (self-describing CSV discipline). `cmd/profiles` is the
  build entry point; `session.OpenMinute`/`MinutesPerSession` give the
  minute range. Determinism is an acceptance criterion project-wide: two
  runs must produce byte-identical files. Universe = 189 symbols from
  `docs/foundations/morning-tape-baskets-v2.json` via `internal/universe`.
