# Mini-spec 8.1 — Archive (S3) + nightly roll + local retention

Status: **open** (written 2026-08-25). Phase 8 = architecture cleanup; this is
its first story. No metric math changes. No trader-facing table changes.
Gated by: Phase 7 merge (done 2026-08-25).

Read first: `CLAUDE.md`, `docs/foundations/data.md` (Cadence + Options sections),
`docs/mini-specs/1.2-live-feeder-capture.md`, `1.4-bucket-store.md`,
`2.1-profile-builder.md`, `7.5-options-backfill.md`, `7.6-options-profiles.md`,
and the Runbook in `7.7-conviction-view.md`.

## Why

The Studio's data volume is at 79% (96 GB free) and `data/` grows ~15 GB per
trading day: equity capture 8.3 GB, options capture 4.4 GB, options full-tape
zip 1.4 GB, equity buckets 450 MB. Nothing is archived anywhere; the Studio is
the only copy of every recorded session. Two nightly rolls exist but one
(options) is manual. This story makes S3 the archive, the Studio a cache, and
one nightly job the owner of every roll.

## What

### A. `internal/archive` — S3 via `aws-sdk-go-v2` (SDK, not CLI — owner decision)

```go
type Class string // "capture" | "capture-options" | "buckets" | "buckets-options" | "full-tape" | "profiles" | "profiles-options" | "flat-files"
type Store interface {
    Put(ctx, class Class, name string, localPath string) error   // multipart via s3/manager; idempotent (skips if remote size+ETag match)
    Get(ctx, class Class, name string, localPath string) error   // .part + rename
    List(ctx, class Class) ([]Object, error)                     // name, size, lastModified
    Exists(ctx, class Class, name string) (bool, error)
}
func Open(cfg Config) (Store, error) // cfg from env: ARCHIVE_S3_BUCKET, ARCHIVE_S3_REGION, ARCHIVE_AWS_ACCESS_KEY_ID, ARCHIVE_AWS_SECRET_ACCESS_KEY
func EnsureLocal(ctx, s Store, class Class, name, localDir string) (path string, err error) // local first; Get on miss
```

Key layout mirrors `data/`: `s3://<bucket>/<class>/<name>` where name is the
local basename (`2026-08-25.csv`, `2026-08-25/stream.jsonl.gz`, `2026-08-25.zip`,
`_floors.csv`, `baskets/semis_compute.csv`). Profiles are uploaded as the whole
directory under a date prefix: `profiles/<through-date>/…` so a rebuild never
overwrites yesterday's artifact.

**Credentials:** `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` already in `.env`
belong to the **vendor's** S3-compatible flat-file endpoint
(`files.massive.com`, see `data/download-trades.py`). They are NOT ours. The
archive uses separately named `ARCHIVE_*` variables so the two can never be
confused. Never log either.

Storage class: `STANDARD_IA` for capture/full-tape/flat-files objects;
`STANDARD` for buckets and profiles (read nightly). Bucket versioning on.

### B. Capture compression

- `internal/capture` and `internal/uwfeed` readers already accept `.jsonl.gz`;
  the writers do not compress (a torn gzip stream would make follow/resume
  harder). Keep that. Compression is a post-session step in the nightly job:
  `gzip -9`-equivalent in Go (`compress/gzip`, BestCompression) → `stream.jsonl.gz`
  next to the original; **verify before delete**: replay the .gz through
  `cmd/replay`/`cmd/replay-options -buckets <scratch>` and require the bucket
  CSV to be byte-identical to the one produced from the raw file (which the
  live run wrote for equity, and which A-day parity already established for
  options). Only then unlink `stream.jsonl`. `manifest.json` is kept alongside.
- `FollowReader` (uwfeed) stays not-gzip-aware; it only ever follows today's
  raw file.

### C. `cmd/nightly` — one job, one LaunchAgent, replaces `com.buddyflow.profiles` and the manual options roll

Runs 22:00 CT weekdays (the existing profiles slot; the UW tape is published
by ~18:10 ET). Steps, each logged with a one-line result, each idempotent,
each failure isolated (a later step runs unless it depends on the failed one):

1. **Options roll**: download `full-tape/<today>.zip` (Go HTTP client, follow
   the 302, `.part` + rename, skip if present and complete) → `uw-backfill`
   logic in-process → `data/buckets-options/<today>.csv` → `profiles-options
   -days 20 -through <today>` → `data/profiles-options/`.
2. **Equity roll**: `data/buckets/<today>.csv` must exist (written by `cmd/live`
   at session end; if missing or `.partial`, regenerate from the capture via the
   replay path and log it) → `profiles -days 20 -through <today>` →
   `data/profiles`.
3. **Compress** yesterday's and today's captures (B), equity and options.
4. **Upload** everything new in every class (Put is idempotent, so this is a
   sync): captures (.gz + manifest), buckets, buckets-options, full-tape zip,
   both profile dirs under `profiles*/<today>/`.
5. **Retention** (local only; S3 keeps everything):
   - `capture/`: keep 5 most recent days locally (gz), delete older **only if**
     `Exists` in S3 with matching size.
   - `capture-options/`: keep 3 days locally, same rule.
   - `full-tape/`: keep 0 locally once uploaded (the bucket CSV is what the
     nightly reads; a zip is only re-read if weights change).
   - `buckets/`, `buckets-options/`: keep 25 days locally (the 20-day window
     plus slack so profile builds never hit the network). Older: delete if in
     S3.
   - `profiles*/`: local dirs are overwritten each night; no retention needed.
   - Reference days (§6: SNDK guide-night open, VIAV→optics morning, a
     de-grossing day) are listed in `docs/foundations/reference-days.json`
     (`{"dates": []}`, owner-maintained) and are **never deleted locally**.
   - Never touch a file whose date is today (a live agent may hold it open).
6. **Disk report**: one line `disk: used=… free=… data/=… classes=…` to the log.
   If free < 40 GB, exit non-zero so launchd's status shows it.

`cmd/nightly` flags: `-date` (default: today in ET), `-dry-run` (log every
action, perform none — required for the first live run), `-skip` (comma list
of step names). Exit codes: 0 all ok, 1 a step failed (which one in the log).

### D. Profile builders read the cache

`cmd/profiles` and `cmd/profiles-options` gain `-archive` (bool, default off):
before day discovery, call `EnsureLocal` for each of the last N trading days'
bucket files so a fresh Studio (or a laptop) can build from S3 alone. No S3
code inside `internal/profile` or `internal/optprofile`; discovery, stamps and
mismatch refusals are unchanged.

## Done when (on recorded data, not live)

1. `internal/archive` unit tests against a local fake (in-memory Store) cover
   Put idempotence, Get .part+rename, EnsureLocal cache-hit/miss; one
   integration test gated by `ARCHIVE_S3_BUCKET` being set round-trips a file
   to the real bucket.
2. A gzipped equity capture and a gzipped options capture each replay to a
   bucket CSV byte-identical to the raw file's (report which dates were used).
3. `cmd/nightly -dry-run -date 2026-08-25` logs the full plan with zero side
   effects; then a real run on a **scratch** copy of `data/` (never the live
   `data/` first — see memory "live smoke tests use scratch -out") produces:
   both profile dirs identical to the current ones, every artifact in S3, local
   retention applied per the table, disk line logged.
4. `profiles -archive` on an empty scratch buckets dir rebuilds
   `data/profiles` byte-identical from S3.
5. `docs/foundations/data.md` gains a "Storage & retention" section stating the
   table in C5, the S3 layout, the credential split, and the reference-days
   file; the 7.7 Runbook's manual evening roll is replaced by "nightly does it;
   to re-run: `bin/nightly -date <date>`". `com.buddyflow.profiles` plist is
   removed, `com.buddyflow.nightly` documented.
6. Zero changes under `internal/ingest`, `internal/feed`, `internal/bucket`,
   `internal/uwfeed/live.go`; equity and options replays remain byte-identical.

## Decisions consumed / owner defaults

- S1 S3 via SDK (owner, 2026-08-25). S2 archive creds are `ARCHIVE_*`, never the
  vendor's AWS pair. S3 local retention: captures 5/3 days, buckets 25 days,
  zips 0 — defaults until the owner overrides. S4 flat-files: archive then
  delete locally (owner confirmed quotes are analysis-only). S5 reference
  days: owner to fill `reference-days.json`; empty list until then.

## Not in this story

Feeder deadline/backoff fixes (uwfeed, backlogged as 8.2), any change to what
the trader sees.

**8.3 (backlog, decided 2026-08-25): repo split along the S3 seam.** The owner
prefers separate repos. Profiles are not split now because they sit between two
Go-typed contracts (bucket CSV → profile; profile CSV → live view), and a split
today means a shared versioned module or duplicated readers. After 8.1 the
contract is the archived data itself: builders read `buckets*/<date>.csv` from
S3 and write `profiles*/<date>/` to S3, the view only reads. **Implementers of
8.1 must keep that seam clean**: every archived class has a documented schema
and stamp in `data.md`; no S3 code inside `internal/profile`, `optprofile`,
`flowshare`, `conviction`. Same seam serves the backlog item "one screen reading
a published live-metric artifact."
