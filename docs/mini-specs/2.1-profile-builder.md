# Mini-spec 2.1 — Session clock & profile builder [F6, F11]

Status: **open** (written 2026-08-15). Story: DEV-PLAN Phase 2 → 2.1.
Ships as **two PRs**: (1) `internal/session` clock package; (2) profile
builder. Context: trimmed for the Monday 2026-08-17 trader POC — the
macro/half-day calendar is deferred to the backlog **top item** (numerically
safe until a half-day enters the lookback; see backlog for the hard
pre-Thanksgiving deadline).

## What

**PR 1 — `internal/session`.** The one tz-correct home for session time:
epoch-ns/epoch-second ↔ ET conversion, minute-bucket alignment, and
session-relative bucket keys ("the 09:35 bucket") for matched-bucket lookups.
Consumers stop doing ad-hoc `time.LoadLocation` math (`cmd/replay`, analysis
scripts today; every Phase 3 metric tomorrow). Kills the November-DST
wrong-bucket failure the matched-baseline invariant forbids.

**PR 2 — profile builder.** 20-day rolling volume profiles per **ticker**
per 1-minute bucket, 09:30–16:00 ET. Bootstrap and roll are the same code
path: **bucket files in, profiles out** — the builder is indifferent to
whether a bucket file came from a live session close, a capture replay, or a
flat-file replay. No REST aggs client is built (vendor-aggregated bars count
volume by SIP conventions that differ from our 0.3 slices; one code path for
history and future makes the counting slice identical by construction).

## Decisions (settled in discussion 2026-08-15)

- **D1 — Bootstrap from trades flat files through the standard pipeline.**
  Download the trailing 20 trading days of trades flat files (quotes not
  needed — profiles are volume-only), replay each through `cmd/replay
  -buckets`, derive minutes with the 1.4 reader. From Monday the nightly
  roll consumes the live session's bucket file; flat-file replay becomes the
  repair path for days whose capture doesn't reconcile clean (1.2 criterion
  4 as a permanent gate).
- **D2 — Counting slice: the $vol slice.** Profile volume per minute =
  CONTINUOUS + BLOCK + NON_PRICE_FORMING (per 0.3/1.4). DUPLICATE, NON_FLOW,
  UNKNOWN never count. CROSS_* excluded — crosses are a separate ledger, and
  including the opening auction would make every 09:30 baseline a cross
  measurement, not a flow measurement. Both share volume and dollar volume
  are profiled per bucket.
- **D3 — Bucket filenames declare session coverage.** Bootstrap files are
  `<date>.trades-only.csv` (the 1.4 `-buckets` validation is opened only for
  this explicitly-named mode; quote counts are honestly zero). Capture-derived
  files that do not span the session are `<date>.partial.csv` (08-13 smoke
  run, 08-14 late start). Baseline day-discovery accepts only `<date>.csv`
  and `<date>.trades-only.csv`; partial files are usable by explicit path
  (RVOL check) but can never be discovered into a baseline.
- **D4 — Storage:** per-ticker self-describing CSVs under `data/profiles/`
  (basket baselines are read-time sums over members — never stored per
  basket). Atomic write, deterministic rebuild.
- **D5 — Statistics (per accepted D6/D5 defaults):** median and MAD ×1.4826
  per (ticker, minute-bucket) across lookback days; MAD=0 falls to the σ
  floor (story 2.2); a ticker contributes to z only after ≥10 profiled days.
- **D6 — Calendar deferred (backlog top item).** Trading days are inferred
  from the data (a day with a flat file / bucket file is a trading day);
  every day is treated as a full day. Interim only — see backlog deadline.

## Done when (all on replayed recorded data)

1. **(PR 1)** Session round-trip and alignment unit tests pass, including a
   DST-boundary case (2026-11-01): the same wall-clock bucket (e.g. 09:35 ET)
   maps to the correct epoch key on both sides of the change.
2. **(PR 2)** Profiles for the full universe build from the 20 replayed
   flat-file days in a single run of nightly-window size.
3. Matched-bucket RVOL ≈ 1.0 sanity check against the replayed 2026-08-14
   buckets at 13:00 ET (capture starts 11:51, so no 09:35 exists for it);
   the formal 09:35 check re-runs on Monday's full session as confirmation,
   not a gate.
4. Determinism: building profiles twice from the same inputs produces
   byte-identical files.
5. ≥10-day exclusion and MAD=0 → floor handoff exercised by unit test.
