## What

Go ingest pipeline with a **source-agnostic core** fed by two interchangeable feeders:

- **Live feeder** — `wss://socket.massive.com/stocks`, subscribes `T.<sym>` + `Q.<sym>`
  for the 189 universe symbols (loaded from `morning-tape-baskets-v2.json`; hot-reload
  required, PM edits config never code). No live run happens before 1.2 exists —
  capture is unconditional from the first live run.
- **File feeder** — streams a flat file (or, later, our own capture files) through the
  identical downstream path. Filters to the universe **in the feeder** — the replay
  analog of the live subscription list; the core never sees a filter. A `--full` flag
  skips the filter for stress testing (whole-market file ≈ 5× universe load), never
  for replay fidelity. Grows into the 1.3 replay harness.

The core: parse messages into internal structs → update the in-memory current-NBBO
table per ticker (the Lee-Ready lookup) → increment counters. **No metrics math** —
Phase 3 plugs in downstream of the NBBO table. Message flow is **capture-before-parse**:
raw bytes are handed to the capture writer (1.2; interface stubbed in 1.1) before/in
parallel with parsing, so a parser fault can never lose data.

## Throughput floor

**≥120k msg/sec** through parse + NBBO update, zero drops, bounded queue depth.
Basis (see capacity appendix): measured combined peak on 2026-08-11 (a CPI day) was
67,815 msg/sec for 1s (09:30:02), 35,820/s over the worst 10s, 5,557/s sustained
09:30–10:30. 120k ≈ 1.75× the measured macro-day burst; decided 2026-08-13
(supersedes the estimated 50k, which the measured burst already exceeded).

## Design constraints

- No per-message heap allocations in the hot loop (pooled/reused buffers).
- NBBO table sharded or per-symbol locked — no single global mutex.
- Bounded queues sized ≥10s of peak (~2M messages ≈ 300MB) with a queue-depth counter.
  Backpressure policy: parse/display may lag (≤5s print→pixel budget); capture never lags.
- Per-symbol `sequence_number` gap counter (vendor-side drop detection; feeds 1.5).
- `pt` (participant timestamp) is absent from the vendor Go client's struct — parse raw
  JSON; confirm on the wire.

## Done when (all on recorded data, not live)

1. The 2026-08-11 flat files stream through the parse path and universe message counts
   match the measured totals exactly: **25,920,623 trades + 45,545,795 quotes**.
2. The 09:29–09:35 burst window replayed at accelerated speed sustains **≥120k msg/sec**
   through parse + NBBO update with zero drops and bounded queue depth.
3. NBBO spot-check: for a sample of (symbol, timestamp) pairs, the maintained NBBO
   matches hand-computed values from the quotes file.
4. Determinism: two identical runs produce identical counts and identical spot-check
   results.

Live-session reconciliation vs vendor totals is *not* the gate (market-closed
development); it becomes a permanent nightly check once live runs begin (1.5).

## Capacity appendix

Throughput measurement + hardware analysis:
`discovery-scripts/flat-file-analysis/output/summary-2026-08-11.md` (script:
`discovery-scripts/flat-file-analysis/throughput.py`). Headline: conservative peak
model 135k msg/s costs ~0.2 core, <2GB RAM, ~22MB/s disk burst on the target machine
(Mac Studio, 48GB, 300GB free) — hardware headroom ≥25× everywhere; the risks are
software patterns (allocation churn, lock contention), addressed by the design
constraints above.
